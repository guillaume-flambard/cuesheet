# Control-surface risks

Prompt-like repo content cannot supply authority. Project IDs resolve from an explicit owner allowlist; canonical directories are fixed, with path traversal and symlink checks. Server mutations are disabled unless owner enables them. Local stdio inherits the launching principal; no unauthenticated HTTP mutation endpoint. Tool annotations and visibility guide hosts, never replace server admission.

Forged mission IDs, stale revisions, duplicate/conflicting submissions, command injection and arbitrary worker targeting refuse before runtime action. Same journal writer lock prevents concurrent terminal/server writers. UI renders strings via text nodes, never untrusted HTML. Bundled assets require no remote scripts/fonts; CSP declares no network/resource domains. Secrets and private transcript/tool output do not enter model/UI payloads. Local configuration contains no credentials.

Restart reads preserved sessions without auto-running. Failed ownership/corrupt journals are blocked. A provider can fail or ignore instructions; existing scoped tools and independent verification remain authoritative. UI never upgrades a proposal to proof. Human check-renewal boundary is derived from exact runtime contract; generic failure is never relabeled human_required.

High risks to verify: same-objective steering, preserved permissions/source, real evidence, host bridge correctness. Any remaining high risk blocks v0 completion.
