# Cuesheet Mission Control

Bounded local MCP App, parallel to the existing terminal projection. Cuesheet owns execution, durable objectives, authority, models, workers, worktrees and proof. Mission Control reads semantic state and routes human intent through the existing producer. Journey 005 and usable selfhost remain open.

MC01: six goal-level tools, useful without UI. MC02: live correction keeps the same session AND objective, including an idle/resumed mission. MC03: state and evidence projected from existing journals; unknown is explicit; no invented progress, workers or costs. MC04: three calm views, accessible and responsive, portable MCP Apps bridge. MC05: mutations require owner-configured local admission; project names map to canonical paths, never client paths. MC06: reproducible real mission, steering and genuine human boundary.

System: MCP transport -> bounded validation/admission -> existing terminal runtime producer -> durable core/usage/view journals -> semantic projection -> concise tool result + UI-only detail -> App iframe. MCP owns no work scheduler or message queue. Read requests never start work. Single-writer ownership remains mandatory.

The runtime has an explicit check-renewal human boundary but no general Siri/human-gate ledger. v0 demonstrates that real existing boundary on Cuesheet; it must not fabricate Siri acceptance or claim selective impact analysis exists. Terminal-owned live sessions cannot be hijacked; this server owns its admitted sessions.

Completion requires real MCP roundtrip, same-objective steering while busy and idle, truthful evidence/replay, human check-renewal delta, UI bridge/render proof and text fallback. Remote deployment/ChatGPT account connection are not presumed from a local proof.

Coverage: core/UX/loading/empty/errors/cancel/resume/persistence/integrity/concurrency/idempotency/authz/privacy/security/accessibility/performance/API/compatibility/diagnostics/unit/integration/runtime/build/docs applicable. Networking limited to local MCP transport plus existing provider route. Offline/provider failures remain blocked, never verified. No new execution migrations, caches, cloud deployment, worker controls, model routing or generic workflow platform. Rollback is disconnecting the MCP server; journals preserved.
