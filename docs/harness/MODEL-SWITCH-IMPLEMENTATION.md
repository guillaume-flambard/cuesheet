# H07.3 : substitution pendant une exécution

DISCOVER : ModelBinding.select refuse busy, et App enregistre la sélection après activation. Une erreur de journal laisse donc la sélection active et le contexte ne porte pas automatiquement le nouveau modèle.

MODEL/SPECIFY : résolution et validation du nouveau provider avant effet. beforeCommit(choice) enregistre la demande via producer.modelSelected (metadata du modèle + événement model) avant activation ; une erreur conserve le binding courant et arrête tout travail si le journal est en défaut. Préparer la préférence globale dans un temporaire avant beforeCommit ; une erreur de journal supprime ce temporaire sans changer les préférences existantes. Une erreur de rename après l’enregistrement durable applique le modèle dans la session et signale séparément la préférence globale non sauvegardée. Préférences et journal sont deux supports, sans atomicité multi-fichiers revendiquée. Un crash entre supports conserve la demande de session, aucune nouvelle inférence ne démarre au chargement.

Une sélection humaine valide peut être appliquée pendant busy. Chaque inférence du binding a son AbortController, combiné au stop de l’exécution ; changement de sélection annule l’ancienne inférence et fait rejeter sa réponse tardive même si le transport ignore abort. Une exception dédiée est reconnue au guard : aucune réponse/outil ancien admis, boucle suivante repart du journal nouveau sans abandonner l’objectif. Les appels déjà commencés gardent le signal d’exécution et leur reçu ; propositions restantes sont refusées par révision de modèle. Changement pendant un outil est annoncé comme en attente de cette frontière. Une résolution/provider invalide ne change rien et n’annule pas le modèle valide.

DECOMPOSE H07.3 : cancellation binding → callback durable avant activation → garde et métadonnées core → UX changement actif → tests. VERIFY : old response ignorant abort propose une mutation refusée ; nouveau modèle reçoit contraintes et ID ; changement pendant outil laisse effet achever une seule fois, rejette la proposition restante ; arrêt humain empêche reprise ; échec de sauvegarde/journal garde ancien binding ; aucun secret dans métadonnées. Fixtures transport ne prouvent pas les résultats d’un modèle réel.
