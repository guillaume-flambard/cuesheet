# Replay: what would the admission gate have refused?

**Date of measurement**: 2026-09-29.
**Tool**: `src/replay.ts` in `guillaume-flambard/cuesheet`, commit below.

## The question

If `cuesheet`'s admission gate had been wired into the real delegation path,
how many of the delegations it would have refused, and were any of those
refusals right?

## Method

1. Read the OpenCode session database read-only (`sqlite3 -readonly`, no write).
2. For every assistant/user text brief, extract the skills it names, matched
   as whole words against the live skill registry (248 skills on this machine
   at the time of measurement).
3. Run the *same* `resolveCapabilities` the live gate uses, against the
   registry as it stood at measurement time.
4. Report the counterfactual, with the false-positive question kept as its own
   number rather than folded into the headline.

## Result, 30-day window

| Measure | Count |
|---|---|
| Text briefs in window | 27 653 |
| Briefs naming at least one skill | 5 059 |
| Would block | **0** |
| Would allow | 5 059 |
| Distinct sessions that would block | 0 |

## What this does and does not say

It does **not** say the admission problem is fake. It says something more
precise, and more useful.

The replay evaluates each brief against the registry that exists *now*. Every
skill named across 30 days of briefs is present in the registry today. So the
historical "an agent could not see a skill that was not there yet" incident
does not surface here, because at replay time the missing skill has since been
created. The gate is measured against a registry that has healed.

This is the same limit ADR-001 records: a would-block is a counterfactual, not
a record of a real failure. The genuinely interesting number, the false
positives, cannot be computed from this replay at all, because it has no record
of what the runtime actually refused.

A zero here is therefore **not** evidence the gate is useless, and it is
**not** evidence it is needed. It is evidence that the failure mode is
time-local: a skill that is missing for a few hours and present for the rest
of its life will never show up in a retrospective scan. Only a gate that runs
at delegation time, in front of a live registry, can see it.

That is the argument for shadow mode, and the reason the number to collect
next is not a replay figure but a live one: `ALLOW`, `WOULD_BLOCK`, and
`UNVERIFIED` logged on every real spawn, with the outcome compared to what
actually happened. `UNVERIFIED` must never collapse silently into either
`ALLOW` or `DENY`; that separation is the whole reason the primitive refuses
when it cannot tell.

## Reproduce

```bash
SINCE=$(( $(date +%s) * 1000 - 30*24*3600*1000 )) LIMIT=1000000 node src/replay.ts
```
